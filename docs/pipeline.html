The seven stages

Blue stages run a local model. Every one is optional, and every one falls back to the deterministic path beneath it — the agent degrades in quality, never in function.

STAGE 1

Template parser

Regex over the simulator's fixed phrasings. Exact, instant, and impossible to hallucinate — so it keeps priority over the model.

re · stdlib
Parses 100% of public-set turns
STAGE 2

LLM extraction

Runs only when the parser falls through. Every extracted value must share a content word with the message, so the model can fail to help but cannot invent a requirement.

Qwen2.5-1.5B-Instruct
"black leather boots in size 9" → color, material, size
STAGE 3

Typed constraint state

Each requirement becomes a record carrying attribute, value, source, turn and status. Provenance decides hardness; status makes retraction surgical rather than destructive.

dataclasses · enums
+0.105 with the reranker · +0.003 alone
STAGE 4A

BM25 sparse route

Field-weighted full-text search. The customer quotes the product's own catalog text, so exact lexical evidence carries most of the signal.

SQLite FTS5
Target in top 100 for 199 / 200 sessions
STAGE 4B

Profile-aware rewrite

Folds the anonymised profile's preference tags into the dense query as weak hints — never allowed to displace a stated requirement.

Qwen2.5-1.5B-Instruct
"basketball shorts polyester breathable"
STAGE 4C

Dense retrieval

Cosine search over precomputed catalog vectors. Replaces the OpenAI embedding call entirely: no key, no network, 5 ms per query.

all-MiniLM-L6-v2 · 384d
50,000 vectors built in 60 s · 77 MB
STAGE 5

Constraint reranker

Routes each typed constraint to the catalog fields where that attribute actually lives — material to features, brand to store — then rewards exact phrases over loose overlap.

offline · hand-weighted
0.748 → 0.854 when added
STAGE 6

Customer reply

One sentence confirming what was understood. The model never sees the products — given them it recited IDs and invented colours, so it gets only the constraints.

Qwen2.5-1.5B-Instruct
~1 s/turn · rejects any reply naming an ASIN
STAGE 7

Question selection

Expected information gain over the live candidate pool picks the next attribute to ask about, masking anything already asked or refused.

Shannon entropy
3.23 → 0.67 bits as the pool converges

What we measured and cut

Four components were built, evaluated over all 200 sessions, and removed from the scoring path. Reporting them is the point: each one is the obvious idea, and each one loses to the simpler system.

ExperimentWhy it should have workedScoreΔVerdict
Sparse baseline Typed state, BM25, constraint reranking 0.853670 — shipped
LLM query rewriting Cleaning the query helps retrieval — worth +0.088 on our other build 0.837511 −0.0162 cut
Global dense fusion Semantic recall should catch what lexical search misses 0.852034 −0.0016 demo only
Entropy question policy Ask the most informative attribute instead of a fixed one 0.827465 −0.0262 demo only
Category-scoped retrieval Restricting to the stated category should raise precision 0.835434 −0.0182 cut
Learned question policy A trained model should beat a fixed rule 0.845883 −0.0078 cut

The common cause: the benchmark's customer quotes the target product's own catalog metadata verbatim — 100% Polyester, Drawstring closure. There is no semantic gap for embeddings to bridge and no conversational grammar for a rewriter to strip, so every "smarter" component trades exact evidence for paraphrase. We kept them behind flags because that reasoning inverts the moment a real shopper types in their own words.
